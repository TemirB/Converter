Конвертер полной истории SMASH OSCAR2013 в ROOT/McDst.

Он читает начальный список, взаимодействия и конечный список каждого события. Для конечных частиц сохраняются конечные импульсы и координаты последнего адронного взаимодействия или распада. Для спектаторов сохраняются координаты из конечного списка и отдельный статус.

Сборка из корня проекта требует GNU Make, компилятор C++17 и ROOT с библиотекой EG. Обычный `make` компилирует программу напрямую, без CMake. По умолчанию исходники McDst берутся из соседнего `../sthbtmaker/StRoot/McDst`; три нужных класса и их ROOT-словарь включаются в исполняемый файл, поэтому готовая библиотека McDst не нужна.

```bash
cd /path/to/Converter
make -j4
make test
```

Исполняемый файл `converter` и метаданные словаря `G__ConverterMcDst_rdict.pcm` находятся в корне `Converter`; объектные файлы — в `.make/`. Запускать конвертер можно из любой директории. При переносе исполняемого файла нужно также переносить файл `.pcm`.

Если `root-config` не находится, подключите окружение установленного ROOT:

```bash
source /path/to/root/bin/thisroot.sh
make -j4
```

Либо укажите путь явно: `make ROOT_CONFIG=/path/to/root/bin/root-config`. Путь к `rootcling` по умолчанию берётся из той же установки ROOT.

Если McDst находится в другом месте:

```bash
make MCDST_SOURCE_DIR=/path/to/McDst
```

Можно использовать установленную библиотеку:

```bash
make MCDST_INCLUDE_DIR=/path/to/McDst/include MCDST_LIBRARY=/path/to/libMcDst.so
```

Для отдельной сборки через CMake сохранён прежний вариант:

```bash
cmake -S . -B build -DMCDST_SOURCE_DIR=/path/to/McDst
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Запуск:

```bash
./converter full_event_history.oscar output.McDst.root
./converter --keep-empty full_event_history.oscar all_events.McDst.root
./converter --root smash.root output.McDst.root
```

Обычный запуск сохраняет события с `scattering_projectile_target yes`, включая чисто упругие. `--keep-empty` сохраняет все события. Число конечных частиц не определяет упругость и не используется для отбора. Для старого флага `empty` смысл yes/no обратный; если флага вообще нет, наличие взаимодействия оценивается по бинарным столкновениям. Такой запасной критерий не различает ядра.

Поддерживаются заголовки до SMASH 3.2 и новые заголовки `# event N ensemble E ...`, а также расширенные записи OSCAR2013 с теми же первыми 12 столбцами. События должны идти последовательно: чередование незавершённых ансамблей не поддерживается и вызывает ошибку.

В конфигурации SMASH нужен полный вывод:

```yaml
Output:
    Collisions:
        Format: ["Oscar2013"]
        Extended: False
        Print_Start_End: Yes
```

`Npart` имеет **транспортное определение**: число уникальных начальных протонов и нейтронов, участвовавших хотя бы в одном адронном взаимодействии. Исходные ID берутся из блока `in`; ограничений на Au+Au или число 394 нет. Спектатор — исходный нуклон без таких взаимодействий. Служебные пересечения стенок/гиперповерхностей и неудавшиеся струнные процессы участниками не делают.

`Ncoll` — число бинарных адронных рассеяний с двумя входящими частицами, включая все виды частиц и упругие процессы; распады и принудительная термализация исключены. Это не глауберовское число неупругих NN-столкновений. Отдельные NN-счётчики также относятся к транспортной истории; они не заменяют расчёт MC Glauber по исходной геометрии. Описание определений записывается в `McEvent.comment` и объект `ConverterDefinitions`.

Дополнительные ветви дерева `McDst`:

| Ветвь | Содержание |
| --- | --- |
| `OscarEnsemble` | Номер ансамбля; для старого формата 0 |
| `InitialNucleons` | Число исходных протонов и нейтронов |
| `SpectatorNucleons` | Число конечных спектаторов |
| `FinalParticles` | Число сохранённых частиц |
| `TransportParticipants` | Полное транспортное Npart |
| `BinaryCollisions` | Полное транспортное Ncoll |
| `NNElasticCollisions` | Рассеяния с двумя входящими нуклонами, type=1 |
| `NNInelasticCollisions` | Остальные бинарные адронные процессы с двумя входящими нуклонами |
| `OscarParticleId` | Исходные OSCAR ID в порядке массива Particle |

Частицы сортируются по исходному ID. `McParticle.index` остаётся последовательным индексом; `status=1` отмечает спектатора, `status=0` — остальные частицы. Координаты −999 больше не используются как метка. Для протонных корреляций нужно явно учитывать этот статус. Родственные связи пока не восстановлены: parent/mate/children имеют значение отсутствия, decay=−1. Это изменение статуса и координат нужно учитывать в потребителях старых файлов.

Поля `McEvent.Npart/Ncoll` хранят Short_t. Если значение превышает 32767, поле содержит −1, а точное значение остаётся в дополнительной Int_t-ветви. Время события берётся из конечного списка, а не из константы 200. OSCAR не сообщает все параметры пучков и сечение; соответствующие поля McRun не калибруются автоматически.

Объекты `InputEvents`, `SkippedEmptyEvents` и `OutputEvents` содержат статистику конвертации. Повреждённые заголовки, неполные блоки, повторные ID, отсутствующая история и EOF внутри события завершают конвертацию с кодом 2 и номером строки. Запись идёт во временный файл рядом с выходом; существующий выход заменяется только после успешного чтения и записи всего входа.

Режим `--root` читает старое дерево `Particles` с npart, impactParameter и векторами t/x/y/z/mass/p0/px/py/pz/pdg/ID/charge. Без полной истории он сохраняет координаты входа, а число участников, столкновений и спектаторов оставляет неизвестным (−1).

Скрипт `generate_and_convert.sh` принимает число задач, число прогонов и имя задания. Пути можно задать через `SMASH_BUILD_DIR`, `CONVERTER_DIR`, `TMP_DIR`, `OSCAR_DST_DIR`, `LOG_DIR` и `ROOTSYS`. При ошибке генерации или конвертации он завершает прогон с ненулевым кодом и сохраняет исходный каталог задачи; успешно обработанные временные каталоги удаляются.

В этом проекте смешивания событий нет. Текущий соседний kT-анализ строит средний фемтоскопический вес по парам одного события; настройки смешанного знаменателя принадлежат `sthbtmaker` и не меняются конвертером. `Force_Decays_At_End` также является настройкой генератора: дочерние частицы сохраняют точки принудительных распадов. Для физических HBT-результатов необходима отдельная проверка зависимости от времени завершения генерации.
