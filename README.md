Конвертер полной истории SMASH OSCAR2013 в ROOT/McDst.

Для перехода уже готовых McDst-файлов из СЦМ в ЛСО есть отдельная программа
[`mcdst_lab`](docs/MCDST_LAB.md). Она принимает входной и выходной каталоги,
распараллеливает обработку по файлам (`--threads`, по умолчанию все доступные потоки)
и сохраняет гистограммы η–pT до/после и множественности без новых отборов.
Основной выход — файлы `*.McDst.root` с деревом `McDst` и ветвями `Event`/`Particle`.
Сборка: `make -j4 mcdst_lab`. Пример: `./mcdst_lab --threads 4 ./cm_files ./lab_files`.

Он читает начальный список `in`, записи `interaction` и конечный список `out` каждого события. Для каждого ID сохраняется последняя полная запись из `in` или `interaction`. Блок `out` определяет только то, какие ID дожили до конца события: их координаты и импульсы берутся из сохранённой истории.

Сборка из корня проекта требует GNU Make, компилятор C++17 и ROOT с библиотекой EG. Обычный `make` компилирует программу напрямую, без CMake. Три нужных класса McDst включены в репозиторий в `vendor/McDst`; они и их ROOT-словарь собираются в исполняемый файл. Соседний репозиторий `sthbtmaker` и готовая библиотека McDst для обычной сборки не нужны.

```bash
cd /path/to/Converter
make -j4
make test
```

Исполняемый файл `converter` и метаданные словаря `G__ConverterMcDst_rdict.pcm` находятся в корне `Converter`; объектные файлы — в `.make/`. Запускать конвертер можно из любой директории. При переносе исполняемого файла нужно также переносить файл `.pcm`.

Если `root-config` не находится, подключите окружение установленного ROOT:

```bash
source /path/to/root/bin/thisroot.sh
make -j4
```

Либо укажите путь явно: `make ROOT_CONFIG=/path/to/root/bin/root-config`. Путь к `rootcling` по умолчанию берётся из той же установки ROOT.

Если нужно использовать свою версию McDst вместо включённой в репозиторий:

```bash
make MCDST_SOURCE_DIR=/path/to/McDst
```

То же для программы ЛСО: `make -j4 mcdst_lab MCDST_SOURCE_DIR=/path/to/McDst`.
Каталог должен содержать `McEvent`, `McParticle`, `McRun` — заголовки `.h` и исходники `.cxx`.

Можно использовать установленную библиотеку:

```bash
make MCDST_INCLUDE_DIR=/path/to/McDst/include MCDST_LIBRARY=/path/to/libMcDst.so
```

Для отдельной сборки через CMake сохранён прежний вариант:

```bash
cmake -S . -B build
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

При необходимости внешнюю версию задают флагом `-DMCDST_SOURCE_DIR=/path/to/McDst`.
В старом каталоге сборки CMake мог сохраниться прежний путь к соседнему проекту;
его можно заменить на `-DMCDST_SOURCE_DIR="$PWD/vendor/McDst" -DMCDST_INCLUDE_DIR="$PWD/vendor/McDst"`.

Запуск:

```bash
./converter full_event_history.oscar output.McDst.root
./converter --keep-empty full_event_history.oscar all_events.McDst.root
./converter --root smash.root output.McDst.root
```

Обычный запуск пропускает события, в заголовке `out` которых указано ровно **394 частицы**. `--keep-empty` отключает этот отбор и сохраняет все события. Флаги `scattering_projectile_target` и `empty` на отбор не влияют. Это восстановленное правило старого конвертера; оно само по себе не определяет физическую упругость события.

Для запуска исходного алгоритма v1 и сравнения с текущей версией:

```bash
./converter --v1 /path/to/full_event_history.oscar v1.McDst.root
./converter --validate /path/to/full_event_history.oscar
./converter --validate /path/to/full_event_history.oscar /path/to/comparison
```

`--validate` последовательно запускает обе версии на одном OSCAR-файле и сохраняет
`current.McDst.root`, `v1.McDst.root`, **`diff.root`** и `diff.csv`. По умолчанию они находятся
в каталоге `<путь-входного-файла>.validation/`; второй аргумент задаёт другой каталог.
При повторном запуске эти четыре файла заменяются. Режимы `--v1` и `--validate`
используют исходный отбор и не совмещаются с `--root` или `--keep-empty`.

В **`diff.root`** находятся гистограммы `TH1D` с разностями **current − v1**:
`diff_px`, `diff_py`, `diff_pz`, `diff_x`, `diff_y`, `diff_z`,
`diff_multiplicity` и `diff_impact_parameter`.
Первые шесть заполняются для совпавших исходных ID частиц; последние две —
один раз на совпавшее событие, включая события с нулевой множественностью.
Диапазоны осей расширяются автоматически. Пропущенные записи не заменяются
нулями: их число видно в гистограммах `event_status` и `particle_status`
с подписями `equal`, `different`, `current_only`, `v1_only`.
Файл также содержит описание сравнения и пути к двум входным ROOT-файлам.
Открыть его можно командой `root -l /path/to/comparison/diff.root`,
например, `diff_px->Draw()` строит распределение разности `px`.

В `diff.csv` есть строка `row_type=event` для каждого события и строка
`row_type=particle` для каждого исходного ID. Для `px`, `py`, `pz`, `x`, `y`, `z`,
`multiplicity` (число записанных частиц) и `impact_parameter` записаны значения
`current_*`, `v1_*` и **`diff_* = current_* − v1_*`**. Единицы: импульсы — ГэВ/c,
координаты и прицельный параметр — фм. Множественность и прицельный параметр
повторяются в строках частиц; строка события сохраняется и при нулевой множественности.
В строках частиц статус `equal`/`different` относится к шести компонентам и PDG;
в строках событий он также учитывает множественность, прицельный параметр
и наличие/совпадение частиц. `current_only`/`v1_only` означает отсутствие
события или частицы в другой версии.
Отсутствующие значения и неопределённые разности остаются пустыми.
Сравнение чисел точное, после записи и чтения ROOT.

Порядок частиц в ROOT может отличаться: сравнение идёт по исходному OSCAR ID,
а индексы массива записаны отдельно в `current_index`/`v1_index`.
Только проверочные ROOT-файлы дополнены ветвью `SourceId`; обычная конвертация
и самостоятельный `--v1` сохраняют прежний набор ветвей.
События сопоставляются по `event_nr` и номеру его появления `event_occurrence`,
начиная с нуля. Это также позволяет сравнивать повторяющиеся номера событий.

Коды завершения: `0` — сравниваемые данные совпали, `3` — найдены различия,
`2` — ошибка чтения, конвертации или записи, `1` — неверные аргументы команды.
Алгоритм v1 сохранён отдельно в `src/OscarConverterV1.cpp`: его разбор заголовков,
три буфера, обход `unordered_map` и отбор событий не исправлялись.
В частности, v1 ожидает заголовки с `ensemble`; различия на входе без `ensemble`
попадут в отчёт. При ошибке текущей версии проверка завершается с кодом `2`.

Поддерживаются заголовки `# event N in/out/end ...` и `# event N ensemble E in/out/end ...`. Заголовок формата `#!OSCAR2013 ...` необязателен. В записях частиц используются первые 12 столбцов `t x y z mass p0 px py pz pdg ID charge`; дополнительные столбцы игнорируются. Служебные комментарии пропускаются. События должны идти последовательно: чередование незавершённых ансамблей не поддерживается и вызывает ошибку.

В конфигурации SMASH нужен полный вывод:

```yaml
Output:
    Collisions:
        Format: ["Oscar2013"]
        Extended: False
        Print_Start_End: Yes
```

В выход попадают только ID, встречавшиеся одновременно в истории и в `out`. Неизвестные конечные ID игнорируются; повторные записи одного ID в истории обновляют сохранённую частицу, а повторы в `out` не создают дополнительные частицы.

Для всех сохранённых частиц с **`ID < 394`** записываются `t=x=y=z=−999`, включая частицы, участвовавшие во взаимодействиях. Импульсы остаются из последней записи истории. Для остальных ID все координаты, время и импульсы сохраняются из этой записи. Такое выделение частиц воспроизводит исходный алгоритм и зависит только от ID.

Отдельный `OscarReader` также выбирает спектаторов только по конечному `ID < 394`.
Упругие рассеяния не снимают эту пометку, поскольку сохраняют ID. Счётчик участников
reader равен числу исходных нуклонов за вычетом сохранившихся исходных нуклонов
с `ID < 394`; история взаимодействий для этой классификации не используется.
Граница рассчитана на Au+Au с исходными ID `0…393`.

Файл содержит дерево `McDst` с ветвями `Event` и `Particle`, а также объект `McRun`. Поля сохраняются в исходном формате:

| Поле | Значение |
| --- | --- |
| `McEvent.eventNr`, `b` | Номер события и прицельный параметр из `end` |
| `McEvent.phi`, `nes`, `stepNr`, `stepT` | `0`, `1`, `1`, `200` |
| `McEvent.Npart`, `Ncoll`, `comment` | `−1`, `−1`, пустая строка |
| `McParticle.index` | Последовательный индекс в массиве |
| `McParticle.status` | `0` для всех частиц |
| `McParticle.parent`, `parentDecay`, `mate`, `decay` | `0`, `0`, `−1`, `0` в конструкторе |
| `McParticle.child` | `−1`, `−1` в конструкторе |

Родственные связи не восстанавливаются; перечисленные аргументы воспроизводят прежний вызов конструктора `McParticle`. Отрицательные индексы в полях McDst с беззнаковым типом при чтении могут иметь значение `65535`. Частицы записываются в порядке первого появления известного ID в `out`. Исходные ID и дополнительные транспортные счётчики отдельными ветвями не записываются.

Чтение OSCAR, обработка событий и запись ROOT собраны в одной функции `OscarConverter::Convert`. Вместо трёх буферов используется одна хеш-таблица: она хранит последнюю запись частицы и отметку о её записи в массив ROOT. Этот массив заполняется при чтении ID из `out`, без повторного обхода всей истории на `end`; само событие записывается только после проверки `end`. Память резервируется заранее, строковый поток и объект `McEvent` переиспользуются. Числовые значения координат и импульсов конечного списка для записи не разбираются. Уровень сжатия ROOT остаётся равным `1`.

Проверяются структура события, совпадение номера события и ансамбля, число записей в `in` и `out`, полнота записей истории и EOF внутри события. Числа записей в заголовках `interaction` не используются для проверки истории. Ошибки завершают конвертацию с кодом `2` и сообщением с номером строки. Запись идёт во временный файл рядом с выходом; существующий выход заменяется только после успешного чтения и записи всего входа.

Режим `--root` читает старое дерево `Particles` с npart, impactParameter и векторами t/x/y/z/mass/p0/px/py/pz/pdg/ID/charge. Без полной истории он сохраняет координаты входа, а число участников, столкновений и спектаторов оставляет неизвестным (−1).

Скрипт `generate_and_convert.sh` принимает число задач, число прогонов и имя задания. Пути можно задать через `SMASH_BUILD_DIR`, `CONVERTER_DIR`, `TMP_DIR`, `OSCAR_DST_DIR`, `LOG_DIR` и `ROOTSYS`. При ошибке генерации или конвертации он завершает прогон с ненулевым кодом и сохраняет исходный каталог задачи; успешно обработанные временные каталоги удаляются.

В этом проекте смешивания событий нет. Текущий соседний kT-анализ строит средний фемтоскопический вес по парам одного события; настройки смешанного знаменателя принадлежат `sthbtmaker` и не меняются конвертером. `Force_Decays_At_End` также является настройкой генератора: дочерние частицы сохраняют точки принудительных распадов. Для физических HBT-результатов необходима отдельная проверка зависимости от времени завершения генерации.
