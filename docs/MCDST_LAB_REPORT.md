# Краткий отчёт о расчётах в `mcdst_lab`

`mcdst_lab` обрабатывает готовые McDst-файлы SMASH: переводит кинематику частиц
из системы центра масс (СЦМ) в лабораторную систему покоя мишени, строит
контрольные распределения и определяет центральность по FXT-множественности.
Это позволяет получить данные для анализа в геометрии
неподвижной мишени и проверить, как смена системы отсчёта влияет на распределение
частиц по направлениям движения.

Отчёт описывает текущую реализацию в `tools/McDstLab*.cpp` и `tools/mcdst_lab.cpp`.
Чтение и обработка частиц находятся в `McDstLabIO.cpp`, расчёт центральности —
в `McDstLabCentrality.cpp`, пакетный запуск — в `McDstLabBatch.cpp`.
Числа ниже — расчётный пример для параметров по умолчанию,
а не результат обработки физической выборки.

## 1. Входные данные и параметры

На вход подаётся каталог ROOT-файлов с деревом `McDst` и ветвями `Event`
(`McEvent`) и `Particle` (`McParticle`). Для каждой записи ожидается одно событие
и массив сохранённых частиц. Программа использует их четырёхимпульсы, координаты,
PDG-коды и данные события; OSCAR и историю взаимодействий она не читает.

Предполагаются симметричные пучки: в исходной СЦМ налетающее ядро (Projectile)
движется вдоль `+z`, мишень (Target) — вдоль `−z`. Энергия столкновения и масса
нуклона задаются пользователем, автоматически из входного файла не определяются.

| Параметр | По умолчанию | Для чего используется |
| --- | --- | --- |
| `--sqrtsnn` | 3 ГэВ | Энергия пары нуклонов в СЦМ, определяет величину буста |
| `--nucleon-mass` | 0.938 ГэВ/c² | Масса нуклона модели, определяет скорость пучков |
| `--eta-max` | 6 | Диапазон гистограмм по псевдобыстроте: `[−6, 6)` |
| `--pt-max` | 3 ГэВ/c | Диапазон гистограмм по поперечному импульсу: `[0, 3)` |

Формула перехода требует `mN > 0` и `sqrt(sNN) > 2mN`. Для асимметричных
пучков она не предназначена. Пределы гистограмм задают область отображения,
отбор частиц по этим пределам не выполняется.

## 2. Переход в систему покоя мишени

В формулах ниже принято `c = 1`. Энергия одного нуклона каждого пучка в СЦМ
равна половине энергии пары. Отсюда рассчитываются параметры Лоренца:

```text
Ebeam = sqrt(sNN) / 2
gamma = Ebeam / mN
beta  = sqrt(1 − 1/gamma²)
```

Мишень в исходных осях имеет скорость `−beta`. Для её остановки программа
выполняет продольный буст, а затем поворот осей вокруг `y` на 180°.
Поворот сохраняет правую систему координат и направляет выходную ось `+z`
против движения Projectile. Итоговое преобразование четырёхимпульса:

```text
E_out  =  gamma (E + beta pz)
px_out = −px
py_out =  py
pz_out = −gamma (pz + beta E)
```

Энергия `E` берётся непосредственно из McDst. По табличной массе частицы она
заново не вычисляется. Для каждой частицы проверяются конечность компонент,
допустимость их хранения в `Float_t` и положительность энергии до и после буста.

Для `sqrt(sNN) = 3 ГэВ` и `mN = 0.938 ГэВ/c²`:

```text
gamma = 1.59914712
beta  = 0.78035775
|pbeam_CM| = sqrt(Ebeam² − mN²) = 1.17053663 ГэВ/c
```

| Номинальный нуклон пучка | `pz` в СЦМ, ГэВ/c | `pz_out`, ГэВ/c | `E_out`, ГэВ |
| --- | ---: | ---: | ---: |
| Target | −1.17053663 | 0 | 0.93800000 |
| Projectile | +1.17053663 | −3.74372056 | 3.85944136 |

Этот пример объясняет и остановку мишени, и знак продольного импульса Projectile
на выходе. При наличии движения Ферми останавливается поступательное движение
ядра; индивидуальные внутренние импульсы его нуклонов сохраняются.

В полном режиме аналогично преобразуется четырёхпозиция частицы:

```text
t_out =  gamma (t + beta z)
x_out = −x
y_out =  y
z_out = −gamma (z + beta t)
```

Координаты выражены в фм, время — в фм/c. Если хотя бы одна из четырёх компонент
равна служебному значению `−999`, вся исходная четырёхпозиция сохраняется:
недостающую координату нельзя согласованно восстановить при бусте.
Импульс такой частицы всё равно преобразуется.

Угол плоскости реакции `Event.phi` изменяется как `pi − phi` с приведением
к `[0, 2pi)`; служебное значение `−999` сохраняется. `Event.stepT` остаётся временем
генератора в СЦМ: после буста пространственно разделённые точки одного исходного
временного слоя имеют разные лабораторные времена.

## 3. Поперечный импульс и псевдобыстрота

Для каждой сохранённой частицы рассчитываются:

```text
pT         = sqrt(px² + py²)
eta_before = asinh(−pz_CM / pT)
eta_after  = asinh(pz_out / pT)
```

`pT` характеризует движение поперёк оси пучка. Продольный буст его не изменяет;
поворот меняет знак `px`, но также сохраняет `pT`. Псевдобыстрота `eta`
характеризует направление импульса и связана с полярным углом формулой
`eta = −ln(tan(theta/2))`. Здесь считается именно псевдобыстрота, а не быстрота.

Минус перед `pz_CM` нужен, чтобы распределения до и после буста использовали
одинаковую ориентацию оси — против Projectile. Иначе сравнение смешивало бы
эффекты смены системы отсчёта и смены направления оси.

Результат записывается в две двумерные гистограммы:

| Объект | Что содержит | Зачем нужен |
| --- | --- | --- |
| `hEtaPtBefore` | Частицы в СЦМ, с осью против Projectile | Исходное распределение для сравнения |
| `hEtaPtAfter` | Те же частицы в системе покоя мишени | Распределение для лабораторного анализа |

Каждая гистограмма имеет 240 бинов по `eta` и 150 по `pT`. При стандартных
диапазонах ширина бина составляет `0.05` и `0.02 ГэВ/c` соответственно.
Каждая частица даёт единицу в один бин. Заполнение идёт по всем сохранённым
частицам, включая нейтральные, лептоны и частицы с неизвестным PDG.
Содержимое — суммарное число частиц на бин; нормировка на число событий,
размер бина и эффективность детектора не выполняется.

Частицы за пределами диапазона попадают в служебные бины underflow/overflow.
Для каждой из двух гистограмм дополнительно сохраняются счётчики:

| Суффикс имени | Что учитывает |
| --- | --- |
| `_outside_plot` | Число заполнений за пределами видимой области хотя бы по одной оси |
| `_axial` | Частицы с `pT = 0`, но ненулевым продольным импульсом: `eta = ±∞`, запись в соответствующий служебный бин |
| `_undefined_eta` | Частицы с нулевым трёхимпульсом: `eta` не определена, гистограмма не заполняется |

Счётчики относятся к своей системе отсчёта. Например, нулевой импульс в СЦМ
после буста может стать ненулевым. `_axial` уже входит в `_outside_plot`;
их нельзя складывать как непересекающиеся категории. Для каждой гистограммы
выполняется баланс:

```text
сумма всех бинов, включая underflow/overflow, + _undefined_eta = LabParticles
```

## 4. Множественности событий

Множественность показывает, сколько частиц определённой категории содержит
событие. Для каждого входного события программа записывает:

| Величина | Как считается | Для чего нужна |
| --- | --- | --- |
| `NAll` | Размер массива `Particle` | Общая сохранённая множественность и контроль числа частиц |
| `NCh` | Число распознанных заряженных адронов и ядерных фрагментов | Анализ адронной множественности |
| `NUnknownPDG` | Число частиц, которые не удалось классифицировать | Контроль полноты `NCh` |

Для известных PDG программа использует базу ROOT: проверяет принадлежность
к мезонам, барионам или ядрам и ненулевой заряд. Ядерные коды `10LZZZAAAI`
дополнительно разбираются по `Z` и `A`; фрагмент с `Z > 0` считается одной
заряженной частицей независимо от числа нуклонов и величины заряда.
Лептоны и фотоны в `NCh` не входят.

Например, для списка `p, n, pi+, pi−, e−, gamma, d, неизвестный PDG`
получится `NAll = 8`, `NCh = 4`, `NUnknownPDG = 1`. Неизвестная частица
остаётся в `NAll`, кинематических гистограммах и выходном дереве; при этом
полнота подсчёта заряженных адронов не гарантируется.

Дерево `LabMultiplicity` содержит `InputEntry`, `EventNr` и эти три счётчика.
Гистограммы `hNAll` и `hNCh` заполняются один раз на событие, включая пустое.
Видимый диапазон охватывает целые множественности 0…65535; большие значения
попадают в overflow, а точное значение остаётся в `LabMultiplicity`.

Буст не добавляет и не удаляет частицы, поэтому множественности в обеих системах
совпадают и рассчитываются один раз. Дополнительного отбора по статусу, признаку
спектатора, `eta` или `pT` нет. События с 394 частицами повторно не исключаются.
Счётчики `NAll` и `NCh` используют все записи массива, предполагая, что вход уже
содержит нужный конечный список. `Nref`, число участников и число столкновений
заново не определяются; существующие поля события сохраняются.

## 5. FXT multiplicity и центральность

Для каждого события дополнительно считается `NFxt` — число распознанных заряженных
частиц в лабораторной системе, удовлетворяющих строгим катам:

```text
−2 < eta_lab < 0
pT > 0.15 ГэВ/c
```

В этом счётчике учитываются заряженные адроны, лептоны, частицы и античастицы,
ядра и антиядра. Фрагмент считается одной частицей. Неизвестный PDG не позволяет
определить заряд и в `NFxt` не входит. Верхнего ката по pT и исключения спектаторов
нет; диапазоны рисунков `--eta-max` и `--pt-max` на этот счётчик не влияют.
Каты относятся только к FXT-счётчику, частицы из выходного McDst не удаляются.

Сначала для всей выбранной выборки строится распределение `H(n)` — число событий
с FXT-множественностью `n`. Затем классы центральности определяются по доле полного
интеграла **справа налево**, от больших множественностей к меньшим:

```text
N = sum H(n), включая события с NFxt = 0
C_low(n)  = 100 × sum[k > n] H(k) / N
C_high(n) = 100 × sum[k >= n] H(k) / N
C(n)      = (C_low(n) + C_high(n)) / 2
```

События с одинаковой множественностью остаются вместе и получают класс по середине
своего процентильного интервала. Из-за целочисленной множественности пограничный
бин может пересекать заданный процент; фактические доли тогда немного отличаются
от номинальных, а на малой выборке отличие может быть большим.

| Класс | Интервал процентиля | Код в `FxtCentralityClass` |
| --- | --- | --- |
| 0–10% | `[0,10)` | `0` |
| 10–30% | `[10,30)` | `1` |
| 30–50% | `[30,50)` | `2` |
| 50–80% | `[50,80)` | `3` |
| Остаток 80–100% | `[80,100)` | `−1` |

FXT-множественность служит признаком для упорядочивания событий: большие значения
соответствуют более центральным классам по этому определению. Это классификация
по распределению выбранных событий; утраченные ранее события и физическая
нормировка на полное сечение автоматически не восстанавливаются.

При запуске по каталогу границы общие для всех успешно обработанных выбранных
файлов. Ошибочные входы исключаются с явным сообщением. Центральность добавляется
после построения распределения; повторное чтение частиц не требуется.
Прямой C++-вызов `Process` для одного файла калибруется только по этому файлу.

| Объект | Что содержит |
| --- | --- |
| `hNFxt` | FXT-распределение событий данного файла |
| `hNFxtReference` | Полное распределение, по которому определены классы |
| `hNFxt_0_10`, `hNFxt_10_30`, `hNFxt_30_50`, `hNFxt_50_80` | FXT-распределения данного файла по четырём классам |
| `hFxtCentrality` | Число событий данного файла в каждом классе и в остатке 80–100% |
| `LabMultiplicity` | Дополнительно: `NFxt`, `FxtCentralityLow`, `FxtCentralityHigh`, `FxtCentralityPercentile`, `FxtCentralityClass` |
| `FxtCentralityMap` | Точная общая таблица множественностей, частот, процентильных интервалов и классов |

При объединении результатов `hNFxtReference` и `FxtCentralityMap` нужно брать
из одного файла запуска: это повторённая общая калибровка. Локальные распределения
разных файлов можно суммировать. В интеграле учитываются и значения выше диапазона
гистограммы; они сохраняются в точной таблице частот.
Для объединения готовых файлов предусмотрен `mcdst_merge`: он сохраняет общие
объекты один раз и суммирует события и локальные распределения. Например:
`make -j4 mcdst_merge`, затем `./mcdst_merge combined.mcDst.root lab_files/`.
Обычный `hadd` без словарей McDst и обработки общих метаданных для этого не подходит.

## 6. Результат и контроль расчёта

В полном режиме для каждого входного файла создаётся отдельный `*.mcDst.root`:
дерево `McDst` с преобразованными частицами, гистограммы, `LabMultiplicity`
и метаданные. PDG-коды, статусы, связи частиц и дополнительные ветви сохраняются.
Неизвестные программе дополнительные наблюдаемые автоматически не преобразуются.

В режиме `--hist-only` создаётся `*.qa.root` с теми же гистограммами
и множественностями, включая FXT и его классы центральности, без дерева `McDst`.
Энергия и продольный импульс после буста
вычисляются для заполнения гистограмм; преобразование координат и запись
обновлённых объектов частиц не выполняются. Режим нужен для быстрого контроля
распределений без сохранения полного набора частиц.

| Метаданные | Назначение |
| --- | --- |
| `LabSqrtsNN`, `LabNucleonMass`, `LabBeta`, `LabGamma` | Воспроизведение параметров перехода |
| `LabEvents`, `LabParticles`, `LabUnknownPDG` | Итоговые числа событий, частиц и записей с неизвестным PDG |
| `LabMaskedPositions` | Число частиц с хотя бы одной координатой `−999` |
| `LabFrame`, `LabSource`, `LabHistOnly` | Соглашения об осях, исходный файл и режим работы |
| `SourceMetadata` | Исходные объекты `McRun`, `TNamed`, `TParameter` верхнего уровня |
| `FxtDefinition`, `FxtEtaMin`, `FxtEtaMax`, `FxtPtMin` | Определение и каты FXT-счётчика |
| `FxtCentralityDefinition`, `FxtCentralityScope`, `FxtCentralityEvents`, `FxtCentralityFiles`, `FxtCentralityFailedFiles` | Способ расчёта центральности, объём выборки и число исключённых файлов |

В полном результате `McRun` также сохраняется на верхнем уровне с обновлёнными
модулями импульсов пучков на нуклон: `pTarg = 0`,
`pProj = 2 gamma sqrt(Ebeam² − mN²)`. Знак движения задаётся описанием осей
в `LabFrame`. Старые входные гистограммы и посторонние деревья не копируются.

Для проверки физической корректности перехода используются сохранение
`E² − px² − py² − pz²`, `pT` и, для известных четырёхпозиций,
`t² − x² − y² − z²`, а также остановка номинального Target.
Эти проверки, баланс частиц в гистограммах и равенство результатов двух режимов
предусмотрены в `tests/mcdst_lab_tests.cpp`. Они не являются отдельными
проверками каждого инварианта при обычном запуске программы. Расчёт ведётся
в `double`, а запись McDst — в `Float_t`, поэтому сравнения требуют допуска
на округление.

## 7. Запуск

Файлы обрабатываются параллельно, события внутри каждого файла — последовательно.
Вложенные каталоги не обходятся. Каждый результат сначала записывается
во временный файл. После построения общего FXT-распределения во временные результаты
добавляются классы центральности, затем заменяются существующие выходные файлы.
По умолчанию обрабатываются все файлы. Для проверки на первых десяти можно
добавить `--max-files 10`; их список предварительно сортируется.

```bash
make -j4 mcdst_lab
./mcdst_lab --threads 4 ./cm_files ./lab_files
```

Контрольные гистограммы без выходного дерева частиц:

```bash
./mcdst_lab --hist-only --threads 4 ./cm_files ./qa_files
```

Сохранение сравнения до/после в PNG и PDF с общей логарифмической цветовой шкалой:

```bash
root -l -b -q 'scripts/plot_lab.C("lab_files/sample.mcDst.root","eta_pt")'
```

Полное FXT-распределение с выделенными цветом классами 0–10%, 10–30%, 30–50%,
50–80% и фактическими числами событий в легенде:

```bash
root -l -b -q 'scripts/plot_fxt.C("lab_files/sample.mcDst.root","fxt_multi")'
```

Описание сверено с [обработкой частиц](../tools/McDstLabIO.cpp),
[расчётом центральности](../tools/McDstLabCentrality.cpp),
[параметрами запуска](../tools/mcdst_lab.cpp),
[существующими тестами](../tests/mcdst_lab_tests.cpp)
и [макросом построения рисунков](../scripts/plot_lab.C).
Подробности сборки и формата результата приведены в [инструкции](MCDST_LAB.md).
