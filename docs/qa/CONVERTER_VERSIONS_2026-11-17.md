# Сравнение версий конвертера на одном событии SMASH

## Результат

На одном событии Au+Au при √sNN = 3 ГэВ и b = 7.5 фм версии **1 и 2 совпали**
по всем 485 конечным частицам: PDG, px/py/pz, энергии, x/y/z и времени.
Множественность и прицельный параметр также совпали.
Независимая проверка непосредственно по OSCAR не обнаружила расхождений.
Спектаторов по правилу «не было неупругих процессов» — **156**;
исходных частиц, встретившихся в неупругих процессах, — **238**.

Версия **0** на исходном файле записала **0 событий**: её сохранённый старый парсер
ожидает `ensemble` в заголовках. SMASH 3.1 выдал `# event 0 in/out/end ...`.
Для сравнения алгоритмов сделана отдельная копия с `ensemble 0` в трёх заголовках
события. Все строки частиц сохранены без изменений; это проверено побайтово.
На этой копии **0 = 1 = 2**, включая все восемь числовых компонент частиц.
Исходный файл и код старого алгоритма не изменялись.

| Вход | Версия 0 | Версия 1 | Версия 2 | Сравнение |
| --- | --- | --- | --- | --- |
| Оригинальный OSCAR | 0 событий | 1 событие, 485 частиц | 1 событие, 485 частиц | 1 = 2; событие отсутствует в 0 |
| Копия с `ensemble 0` | 1 событие, 485 частиц | 1 событие, 485 частиц | 1 событие, 485 частиц | Все три совпали |

Совпадение 1 и 2 на этом событии согласуется с реализацией SMASH: обычные упругие
процессы сохраняют ID, а после неупругих выдаются новые ID. При исходных ID 0…393
это даёт тот же отбор, что и старая граница 394. Версия 2 определяет участие
непосредственно по процессам и не требует такого соглашения о нумерации.

## Три режима

| Значение `--version` | Реализация |
| --- | --- |
| `0` | Старый алгоритм `OscarConverterV1`, включая исходные ограничения парсера и отбор событий |
| `1` | Существующий оптимизированный алгоритм; используется по умолчанию |
| `2` | Та же последняя запись истории, но пометка спектатора устанавливается по неупругим процессам |

В версии 2 только упругие рассеяния не снимают пометку спектатора.
После первого неупругого процесса частица считается участвовавшей.
Её более поздние упругие рассеяния обновляют координаты и импульсы как раньше.
Это изменение классификации спектаторов, а не переход к координатам последнего
неупругого взаимодействия.

Неупругие типы: `2–5`, `7`, `9–15`, `41–46`. Типы `0`, `1`, `6`, `8`, `90`
не устанавливают неупругое участие. Тип `47` требует отдельного переноса
пометок с соответствующих входящих частиц: неудавшийся струнный процесс
заменяется упругим рассеянием, при этом ID меняются.
Правила сверены с исходниками установленного SMASH 3.1:
`src/action.cc`, `src/scatteraction.cc`, `src/oscaroutput.cc`.

Прежние `--v1`, `--validate`, `--root`, `--keep-empty` сохранены.
Исторический `--v1` означает **0** в новой нумерации.
Обычные результаты не получают проверочную ветвь `SourceId`;
она добавляется только при сравнении версий.

## Генерация и состав события

- SMASH 3.1, Linux, ROOT 6.28.
- Au+Au, √sNN = 3 ГэВ, `Fermi_Motion: frozen`.
- `Nevents: 1`, `Randomseed: 246813579`, `Impact.Value: 7.5` фм.
- `End_Time: 200`, `Force_Decays_At_End: true`.
- Начальных частиц: 394; конечных: 485.

| Тип процесса | Описание | Количество |
| --- | --- | --- |
| 1 | Упругое рассеяние | 754 |
| 2 | Образование резонанса | 336 |
| 3 | Неупругое 2 → 2 | 161 |
| 5 | Распад резонанса | 419 |
| 45 | Мягкий недифракционный струнный процесс | 4 |

Первое пробное событие со случайным b = 14.642 фм содержало 394 конечные частицы
и пропускалось исходным отбором всех версий. Поэтому содержательное сравнение
выполнено на одном дополнительно сгенерированном событии с фиксированным b.
Первый файл также сохранён. Конфигурация генератора в `build/config.yaml` не менялась:
для сравнения создана отдельная копия настроек.

## Где лежат результаты на Ubuntu

Базовый каталог:

```text
/home/ubuntu/Temir/smash/build/data/Converter/validation/interaction-types-20261116/
```

- `config-b7p5.yaml` — настройки проверенного события.
- `event-comparison/full_event_history.oscar` — исходное событие.
- `event-comparison/with-ensemble.oscar` — копия для проверки версии 0.
- `source_snapshot/converter` — собранная программа с тремя режимами.
- `comparison-raw/`, `comparison-ensemble/` — три ROOT-результата и три попарных сравнения CSV/ROOT.
- `audit.json` — независимая сверка, SHA-256 входа, числа событий/частиц и времена.
- `build-and-tests.log` — сборка и тесты на Ubuntu.

Существующая сборка `Converter/converter` на Ubuntu не заменялась: проверочная
программа собрана в отдельном `source_snapshot`. Локально обновлён основной код
и собран обычный `./converter`.

Запуск из корня проекта после сборки:

```bash
make -j4 converter
./converter --version 0 input.oscar version0.McDst.root
./converter --version 1 input.oscar version1.McDst.root
./converter --version 2 input.oscar version2.McDst.root
./converter --validate-all input.oscar comparison/
```

`--validate-all` создаёт пары `diff_1_0`, `diff_2_0`, `diff_2_1` в CSV/ROOT.
В каждой паре разность равна первой версии минус вторая.
Сравниваются исходные ID частиц, а не их порядок в массиве.
Код возврата `3` означает различия, включая отсутствие события в версии 0;
код `2` означает ошибку конвертации/сравнения.

Времена записаны в `timings.csv`, но не используются для вывода об ускорении:
проверка одного события и последовательный запуск версий дают заметный вклад
инициализации ROOT в первый запуск.

## Проверки кода

`make -j4 test converter` прошёл локально и на Ubuntu с ROOT 6.28.
Два тестовых набора также прошли с AddressSanitizer/UBSan.
Проверены только упругие и неупругие истории, распады, последующие упругие
рассеяния, исходные ID вне диапазона 0…393, сохранённый низкий ID после неупругого
процесса, техническое пересечение стенки, перенос пометок в типе 47, сброс
состояния между событиями, отбор 394 и `--keep-empty`.
Некорректные типы и размеры блоков отклоняются с сохранением прежнего выхода.
Сравнение отдельно проверено на различиях только энергии/времени.

Машиночитаемый результат проверки: [converter-versions-audit.json](converter-versions-audit.json).
