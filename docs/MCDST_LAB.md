# Обработка готовых McDst в лабораторной системе

`mcdst_lab` — отдельная программа C++17/ROOT. Она не вызывает конвертер и не читает OSCAR.
Вход: каталог готовых файлов с деревом `McDst` и массивами `Event` (`McEvent`),
`Particle` (`McParticle`). Предполагается симметричный коллайдер в СЦМ SMASH:
Projectile движется вдоль +z, Target — вдоль −z.

```bash
make -j4 mcdst_lab
./mcdst_lab /path/to/cm_files /path/to/lab_files
./mcdst_lab --threads 4 /path/to/cm_files /path/to/lab_files
./mcdst_lab --hist-only --threads 4 /path/to/cm_files /path/to/qa_files
```

Программа обрабатывает непосредственно лежащие во входном каталоге файлы `*.root`.
Вложенные каталоги не обходятся. Выходной каталог создаётся, имена файлов сохраняются.
Один файл обрабатывается одним потоком; `--threads all` (по умолчанию) использует число
аппаратных потоков, но не больше числа файлов. `--threads 1` даёт последовательный режим.
Каталоги входа и выхода должны различаться. Файл, уже содержащий маркер `LabFrame`,
не допускается к повторному бусту.

События внутри файла читаются последовательно, без накопления всей выборки.
Каждый рабочий поток имеет собственные ROOT-файлы, дерево, гистограммы и буферы.
Операции ROOT защищены через `ROOT::EnableThreadSafety`; внутренний параллелизм ROOT
не включается. Общая таблица классификации PDG заполняется до запуска рабочих потоков
и далее только читается. Расход ОЗУ растёт с числом одновременно обрабатываемых файлов:
на поток приходится кэш чтения 8 МиБ, примерно 1.6 МиБ содержимого гистограмм,
буферы ROOT и одно распакованное событие. Это не оценка полного RSS процесса.
При ограниченной памяти задайте меньше потоков. Для одного большого файла дополнительные
потоки не используются.

`--hist-only` не записывает дерево частиц, не преобразует координаты и не читает
дополнительные ветви McDst. Он сохраняет обе гистограммы и таблицу множественностей.
Экспорт рисунков выполняется отдельно, чтобы не тратить время на графику при обработке файлов.

Запись каждого результата идёт через временный файл рядом с выходом. Уже существующий
результат заменяется только после успешной обработки файла. Ошибка одного входа не
прерывает остальные; итоговый код возврата — `2`, если хотя бы один файл не обработан,
`1` при ошибке аргументов, `0` при полном успехе. Успешные результаты при частичном сбое
сохраняются. Ошибочные/чужие ROOT-файлы не пропускаются молча.

Сборка через CMake также поддерживается:

```bash
cmake -S . -B build
cmake --build build --target mcdst_lab --parallel 4
./build/mcdst_lab --threads 4 ./cm_files ./lab_files
```

Требования к ROOT и McDst и переменные `ROOT_CONFIG`, `MCDST_SOURCE_DIR`,
`MCDST_INCLUDE_DIR`, `MCDST_LIBRARY` те же, что у конвертера. При сборке из исходников
McDst их словарь входит в программу. `make mcdst_lab` не компилирует реализацию конвертера.
При переносе программы нужно также перенести соответствующий файл словаря `.pcm`.

## Физическое преобразование

Параметры по умолчанию соответствуют предоставленному конфигу Au+Au:
`--sqrtsnn 3 --nucleon-mass 0.938` (ГэВ). Масса — значение модели SMASH, а не масса
протона из таблицы ROOT. Для других параметров генерации их необходимо указать явно.
Программа не определяет энергию или исходную СО по распределению конечных частиц.
Асимметричные пучки не поддерживаются этой формулой.

При `Ebeam = sqrtsnn/2`:

```text
gamma = Ebeam / mN = 1.59914712
beta  = sqrt(1 - 1/gamma²) = 0.78035775

E_lab  = gamma (E + beta pz)
pz_lab = gamma (pz + beta E)
t_lab  = gamma (t + beta z)
z_lab  = gamma (z + beta t)
```

После буста выполняется поворот системы осей вокруг y на 180°:
`(x,y,z) -> (-x,y,-z)` и `(px,py,pz) -> (-px,py,-pz)`. Так система остаётся правой,
а положительная продольная ось направлена против движущегося Projectile.
Номинальный Target покоится, импульс Projectile на нуклон в выходных осях
примерно `−3.74372056 ГэВ/c`. При `Fermi_Motion: frozen` остановлено поступательное
движение ядра; внутренние импульсы нуклонов не обнуляются.

Энергия берётся из McDst, не пересчитывается через табличную массу частицы.
Преобразование вычисляется в `double`; McDst хранит компоненты в `Float_t`, поэтому
проверки инвариантов учитывают его точность. После буста номинально нулевой импульс
мишени может иметь небольшой остаток от округления исходного файла.

Если **любая** компонента четырёхпозиции равна служебному `−999`, вся четырёхпозиция
сохраняется буквально: частично известную точку нельзя согласованно преобразовать.
Это не влияет на импульсы и не является критерием исключения частицы.
Полные физические четырёхпозиции преобразуются. Угол `Event.phi` поворачивается как
`pi - phi` с приведением к `[0,2pi)`; его значение `−999` сохраняется.
`Event.stepT` остаётся временем генератора в исходной СЦМ: единого лабораторного
времени для пространственно разделённых точек исходного временного слоя нет.

Формулы: [PDG, Kinematics](https://pdg.lbl.gov/2023/reviews/rpp2023-rev-kinematics.pdf).
Направления пучков: [SMASH ColliderModus](https://theory.gsi.de/~smash/doc/2.2/classsmash_1_1ColliderModus.html).
Масса нуклона: [SMASH constants.h](https://raw.githubusercontent.com/smash-transport/smash/main/src/include/smash/constants.h).

## Содержимое результата

| Объект | Значение |
| --- | --- |
| `McDst` | Исходная структура дерева и все события, с преобразованными импульсами и физическими координатами; отсутствует при `--hist-only` |
| `hEtaPtBefore` | Конечные частицы до буста, уже с осью против Projectile |
| `hEtaPtAfter` | Те же частицы после буста, с той же ориентацией оси |
| `hNAll`, `hNCh` | Распределения множественности по событиям, включая пустые события |
| `LabMultiplicity` | `InputEntry`, `EventNr`, `NAll`, `NCh`, `NUnknownPDG`; одна запись на входное событие |
| `LabFrame`, `LabSource` | Соглашения о СО и путь к исходному файлу |
| `LabSqrtsNN`, `LabNucleonMass`, `LabBeta`, `LabGamma` | Параметры преобразования |
| `LabEvents`, `LabParticles`, `LabUnknownPDG`, `LabMaskedPositions`, `LabHistOnly` | Итоговые счётчики и режим |
| `SourceMetadata` | Исходные объекты `McRun`, `TNamed`, `TParameter` верхнего уровня |

Исходные гистограммы, другие деревья и каталоги не копируются: они относятся к исходной
СО. Объекты `McRun` также записываются на верхнем уровне полного результата с обновлёнными
**модулями** импульсов пучков на нуклон: `pProj = 3.74372056`, `pTarg = 0` для параметров
по умолчанию. Остальные поля McRun сохраняются, включая неизвестные A/Z, если их не
заполнил конвертер. Направление Projectile задано метаданными `LabFrame`.

PDG, статусы, связи, индексы, прицельный параметр, число участников/столкновений и
дополнительные ветви McDst сохраняются. Сторонние дополнительные ветви сохраняют
исходный смысл: программа не пытается преобразовывать неизвестные ей координаты
или наблюдаемые. Нового отбора событий, в том числе повторного исключения `N=394`, нет.

`NAll` — число всех сохранённых конечных частиц. `NCh` — число заряженных адронов,
включая ядра/фрагменты (каждый фрагмент считается одной частицей), без лептонов и фотонов.
Классификация известных частиц берётся из ROOT PDG; для ядер используется код `10LZZZAAAI`.
Неизвестный PDG сохраняется в дереве, входит в `NAll` и гистограммы, но учитывается
отдельно в `NUnknownPDG`. При ненулевом значении `NCh` неполон, о чём программа сообщает.
Ограничений по η, pT и правил исключения спектаторов нет. Множественности одинаковы в обеих
СО, поэтому записываются один раз. Центральность и `Nref` пока не определяются.

## Гистограммы и рисунки

По горизонтали всегда **псевдобыстрота**, не быстрота:

```text
pT = hypot(px, py)
eta_before = asinh(-pz_CM / pT)
eta_after  = asinh(pz_output / pT)
```

Гистограммы имеют 240×150 бинов, диапазоны по умолчанию η ∈ [−6,6),
pT ∈ [0,3) ГэВ/c. Их можно изменить через `--eta-max` и `--pt-max`.
Это необработанные числа частиц на бин, без нормировки на событие, площадь бина или веса.
Выход за границы рисунка **не отбрасывает частицу**: используются underflow/overflow-бин,
а число таких записей хранится в `<имя_гистограммы>_outside_plot`.

При pT=0 и ненулевом продольном импульсе η бесконечна: запись попадает в соответствующий
крайний служебный бин и счётчик `_axial`. При нулевом трёхимпульсе η не определена:
запись идёт только в `_undefined_eta`, но остаётся в McDst и множественностях.
Сумма всех бинов, включая служебные, плюс `_undefined_eta` равна `LabParticles`.
Гистограммы множественности содержат целочисленные значения 0…65535; большие значения
попадают в overflow, а точное число остаётся в `LabMultiplicity`.

Сравнение двух гистограмм с общей цветовой шкалой, PNG и PDF:

```bash
root -l -b -q 'scripts/plot_lab.C("lab_files/sample.root","eta_pt")'
```

Макрос визуализации работает и с полным результатом, и с `--hist-only`.
Для объединения результатов одной выборки с одинаковыми настройками можно суммировать
гистограммы средствами ROOT. Счётчики/параметры и таблица `InputEntry` относятся к каждому
входному файлу; после механического объединения их нельзя считать глобальными идентификаторами.

## Проверки

```bash
make -j4 test-lab
# или после сборки теста через CMake:
ctest --test-dir build -R mcdst_lab_tests --output-on-failure
```

Тесты проверяют остановку Target, ускорение и направление Projectile, сохранение массы,
pT и пространственно-временного интервала, служебные координаты, пустые события и
события с 394 частицами, заряженные/нейтральные адроны, лептоны, фрагменты и неизвестные PDG,
знаки η, учёт служебных бинов, дополнительные ветви, split/unsplit McDst,
эквивалентность гистограмм обоих режимов, параллельную обработку каталогов и сохранность
существующего результата при ошибке. Исходные файлы проверяются на неизменность.
