# Обработка готовых McDst в лабораторной системе

`mcdst_lab` — отдельная программа C++17/ROOT. Она не вызывает конвертер и не читает OSCAR.
Вход: каталог готовых файлов с деревом `McDst` и массивами `Event` (`McEvent`),
`Particle` (`McParticle`). Предполагается симметричный коллайдер в СЦМ SMASH:
Projectile движется вдоль +z, Target — вдоль −z.

Код разделён по этапам обработки:

| Файл | Ответственность |
| --- | --- |
| [`McDstLab.cpp`](../tools/McDstLab.cpp) | Переход между системами отсчёта, обработка одного файла и безопасная замена результата |
| [`McDstLabIO.cpp`](../tools/McDstLabIO.cpp) | Чтение McDst, обработка частиц, счётчики, гистограммы и метаданные |
| [`McDstLabCentrality.cpp`](../tools/McDstLabCentrality.cpp) | Калибровка центральности и запись классов событий |
| [`McDstLabBatch.cpp`](../tools/McDstLabBatch.cpp) | Выбор файлов, потоки и общая калибровка выборки |
| [`McDstLabMerge.cpp`](../tools/McDstLabMerge.cpp) | Слияние готовых результатов с однократным сохранением общей калибровки |
| [`mcdst_lab.cpp`](../tools/mcdst_lab.cpp) | Разбор аргументов командной строки |

```bash
make -j4 mcdst_lab
./mcdst_lab /path/to/cm_files /path/to/lab_files
./mcdst_lab --threads 4 /path/to/cm_files /path/to/lab_files
./mcdst_lab --hist-only --threads 4 /path/to/cm_files /path/to/qa_files
```

Программа обрабатывает непосредственно лежащие во входном каталоге файлы `*.root`.
Вложенные каталоги не обходятся. Выходной каталог создаётся. В основном режиме
результаты имеют формат McDst: дерево `McDst`, ветви `Event`/`Particle` и объекты
`McEvent`/`McParticle`. Имя `sample.root` превращается в `sample.mcDst.root`;
готовый суффикс `.McDst` не дублируется, его регистр приводится к `.mcDst.root`.
Если несколько входов дают одно выходное имя (например, `sample.root` и
`sample.mcDst.root`), запуск завершается до начала записи.
Один файл обрабатывается одним потоком; `--threads all` (по умолчанию) использует число
аппаратных потоков, но не больше числа файлов. `--threads 1` даёт последовательный режим.
Каталоги входа и выхода должны различаться. Файл, уже содержащий маркер `LabFrame`,
не допускается к повторному бусту.

События внутри файла читаются последовательно, без накопления всей выборки.
Каждый рабочий поток имеет собственные ROOT-файлы, дерево, гистограммы и буферы.
Операции ROOT защищены через `ROOT::EnableThreadSafety`; внутренний параллелизм ROOT
не включается. Общая таблица классификации PDG заполняется до запуска рабочих потоков
и далее только читается. Расход ОЗУ растёт с числом одновременно обрабатываемых файлов:
на поток приходится кэш чтения 8 МиБ, примерно 2.1 МиБ содержимого гистограмм,
буферы ROOT и одно распакованное событие. Также сохраняются компактные таблицы частот
FXT-множественности по файлам. Это не оценка полного RSS процесса.
При ограниченной памяти задайте меньше потоков. Для одного большого файла дополнительные
потоки не используются.

`--hist-only` предназначен для отдельного QA-режима: он записывает `sample.qa.root`
с гистограммами, множественностями и FXT-центральностью, без дерева частиц, преобразования
координат и чтения дополнительных ветвей McDst. Для выхода в формате McDst запускайте
основной режим без этого флага.
Экспорт рисунков выполняется отдельно, чтобы не тратить время на графику при обработке файлов.

Запись каждого результата идёт через временный файл рядом с выходом. После обработки
всех файлов строится общая FXT-центральность и добавляется в таблицы событий;
деревья частиц повторно не читаются. Уже существующие результаты заменяются после
успешного завершения этого этапа. Ошибка одного входа не
прерывает остальные; итоговый код возврата — `2`, если хотя бы один файл не обработан,
`1` при ошибке аргументов, `0` при полном успехе. Успешные результаты при частичном сбое
сохраняются. Ошибочные/чужие ROOT-файлы не пропускаются молча.
Перед обработкой число записей в читаемых ветвях, включая вложенные split-ветви,
сверяется с деревом. Чтение каждой ветви проверяется отдельно, чтобы неполная
ветвь не приводила к повторному использованию частиц или события предыдущей записи.

Сборка через CMake также поддерживается:

```bash
cmake -S . -B build
cmake --build build --target mcdst_lab --parallel 4
./build/mcdst_lab --threads 4 ./cm_files ./lab_files
```

Для обычной сборки достаточно ROOT, GNU Make и компилятора C++17. Исходники трёх
классов McDst находятся в `vendor/McDst`; внешний репозиторий `sthbtmaker` не требуется.
Переменные `ROOT_CONFIG`, `MCDST_SOURCE_DIR`, `MCDST_INCLUDE_DIR`, `MCDST_LIBRARY`
те же, что у конвертера, и позволяют явно выбрать другую установку ROOT или McDst.
При сборке из исходников McDst их словарь входит в программу.
`make mcdst_lab` не компилирует реализацию конвертера.
При переносе программы нужно также перенести соответствующий файл словаря `.pcm`.

Если старая копия проекта на другом компьютере сообщает
`No rule to make target '../sthbtmaker/StRoot/McDst/McEvent.h'`, обновите исходники
проекта вместе с каталогом `vendor/McDst`. Затем запустите `make -j4 mcdst_lab`.
В старой версии без включённых классов укажите существующий внешний McDst явно:
`make -j4 mcdst_lab MCDST_SOURCE_DIR=/actual/path/to/sthbtmaker/StRoot/McDst`.

## Физическое преобразование

Параметры по умолчанию соответствуют предоставленному конфигу Au+Au:
`--sqrtsnn 3 --nucleon-mass 0.938` (ГэВ). Масса — значение модели SMASH, а не масса
протона из таблицы ROOT. Для других параметров генерации их необходимо указать явно.
Программа не определяет энергию или исходную СО по распределению конечных частиц.
Асимметричные пучки не поддерживаются этой формулой.

При `Ebeam = sqrtsnn/2`:

```text
gamma = Ebeam / mN = 1.59914712
beta  = sqrt(1 - 1/gamma²) = 0.78035775

E_lab  = gamma (E + beta pz)
pz_lab = gamma (pz + beta E)
t_lab  = gamma (t + beta z)
z_lab  = gamma (z + beta t)
```

После буста выполняется поворот системы осей вокруг y на 180°:
`(x,y,z) -> (-x,y,-z)` и `(px,py,pz) -> (-px,py,-pz)`. Так система остаётся правой,
а положительная продольная ось направлена против движущегося Projectile.
Номинальный Target покоится, импульс Projectile на нуклон в выходных осях
примерно `−3.74372056 ГэВ/c`. При `Fermi_Motion: frozen` остановлено поступательное
движение ядра; внутренние импульсы нуклонов не обнуляются.

Энергия берётся из McDst, не пересчитывается через табличную массу частицы.
Преобразование вычисляется в `double`; McDst хранит компоненты в `Float_t`, поэтому
проверки инвариантов учитывают его точность. После буста номинально нулевой импульс
мишени может иметь небольшой остаток от округления исходного файла.

Если **любая** компонента четырёхпозиции равна служебному `−999`, вся четырёхпозиция
сохраняется буквально: частично известную точку нельзя согласованно преобразовать.
Это не влияет на импульсы и не является критерием исключения частицы.
Полные физические четырёхпозиции преобразуются. Угол `Event.phi` поворачивается как
`pi - phi` с приведением к `[0,2pi)`; его значение `−999` сохраняется.
`Event.stepT` остаётся временем генератора в исходной СЦМ: единого лабораторного
времени для пространственно разделённых точек исходного временного слоя нет.

Формулы: [PDG, Kinematics](https://pdg.lbl.gov/2023/reviews/rpp2023-rev-kinematics.pdf).
Направления пучков: [SMASH ColliderModus](https://theory.gsi.de/~smash/doc/2.2/classsmash_1_1ColliderModus.html).
Масса нуклона: [SMASH constants.h](https://raw.githubusercontent.com/smash-transport/smash/main/src/include/smash/constants.h).

## Содержимое результата

| Объект | Значение |
| --- | --- |
| `McDst` | Исходная структура дерева и все события, с преобразованными импульсами и физическими координатами; отсутствует при `--hist-only` |
| `hEtaPtBefore` | Конечные частицы до буста, уже с осью против Projectile |
| `hEtaPtAfter` | Те же частицы после буста, с той же ориентацией оси |
| `hNAll`, `hNCh` | Распределения множественности по событиям, включая пустые события |
| `hNFxt` | FXT-множественность событий данного файла |
| `hNFxtReference` | Общее распределение FXT по всей выборке, использованное для центральности |
| `hNFxt_0_10`, `hNFxt_10_30`, `hNFxt_30_50`, `hNFxt_50_80` | Распределения FXT событий данного файла по четырём классам |
| `hFxtCentrality` | Число событий данного файла в каждом классе, включая остаток 80–100% |
| `LabMultiplicity` | `InputEntry`, `EventNr`, `NAll`, `NCh`, `NUnknownPDG`, `NFxt`, `FxtCentralityLow`, `FxtCentralityHigh`, `FxtCentralityPercentile`, `FxtCentralityClass` |
| `FxtCentralityMap` | Общая таблица: `NFxt`, число событий `Events`, `PercentileLow`, `PercentileHigh`, `Percentile`, `Class` |
| `FxtDefinition`, `FxtEtaMin`, `FxtEtaMax`, `FxtPtMin` | Определение FXT и значения катов |
| `FxtCentralityDefinition`, `FxtCentralityScope`, `FxtCentralityEvents`, `FxtCentralityFiles`, `FxtCentralityFailedFiles` | Определение и объём выборки для центральности |
| `LabFrame`, `LabSource` | Соглашения о СО и путь к исходному файлу |
| `LabSqrtsNN`, `LabNucleonMass`, `LabBeta`, `LabGamma` | Параметры преобразования |
| `LabEvents`, `LabParticles`, `LabUnknownPDG`, `LabMaskedPositions`, `LabHistOnly` | Итоговые счётчики и режим |
| `SourceMetadata` | Исходные объекты `McRun`, `TNamed`, `TParameter` верхнего уровня |

Исходные гистограммы, другие деревья и каталоги не копируются: они относятся к исходной
СО. Объекты `McRun` также записываются на верхнем уровне полного результата с обновлёнными
**модулями** импульсов пучков на нуклон: `pProj = 3.74372056`, `pTarg = 0` для параметров
по умолчанию. Остальные поля McRun сохраняются, включая неизвестные A/Z, если их не
заполнил конвертер. Направление Projectile задано метаданными `LabFrame`.

PDG, статусы, связи, индексы, прицельный параметр, число участников/столкновений и
дополнительные ветви McDst сохраняются. Сторонние дополнительные ветви сохраняют
исходный смысл: программа не пытается преобразовывать неизвестные ей координаты
или наблюдаемые. Нового отбора событий, в том числе повторного исключения `N=394`, нет.

`NAll` — число всех сохранённых конечных частиц. `NCh` — число заряженных адронов,
включая ядра/фрагменты (каждый фрагмент считается одной частицей), без лептонов и фотонов.
Классификация известных частиц берётся из ROOT PDG; для ядер используется код `10LZZZAAAI`.
Неизвестный PDG сохраняется в дереве, входит в `NAll` и гистограммы, но учитывается
отдельно в `NUnknownPDG`. При ненулевом значении `NCh` неполон, о чём программа сообщает.
Для `NAll` и `NCh` ограничений по η, pT и правил исключения спектаторов нет.
Эти множественности одинаковы в обеих СО, поэтому записываются один раз.
`Nref` пока не определяется.

## FXT multiplicity и классы центральности

`NFxt` — число **всех распознанных заряженных частиц**, включая лептоны,
античастицы и ядерные фрагменты, с катами в выходной системе покоя мишени:

```text
−2 < eta_lab < 0
pT > 0.15 ГэВ/c
eta_lab = asinh(pz_output / pT)
```

Границы строгие. Верхнего ката по pT и исключения спектаторов нет.
Фрагмент считается одной частицей. Неизвестные PDG исключены из `NFxt`, поскольку
их заряд неизвестен; ненулевой `NUnknownPDG` указывает на возможную неполноту.
`--eta-max` и `--pt-max` меняют только рисунки и не влияют на FXT.
Отбор используется для счётчика, все частицы в выходном McDst сохраняются.

Сначала строится распределение FXT по событиям, затем определяется центральность
по доле **полного интеграла событий справа налево**, от больших `NFxt` к меньшим.
Для запуска по каталогу используется одна общая выборка успешно обработанных
файлов, выбранных через `--max-files`; без этого ограничения — все файлы.
Ошибочные файлы исключаются с сообщением и счётчиком `FxtCentralityFailedFiles`.
Вызов C++ `Process` для одного файла использует только его события.
В знаменатель входят все события этой выборки, включая `NFxt = 0` и пустые события.
Нормировка на потерянные на предыдущих этапах события не восстанавливается.

Пусть `H(n)` — число событий с `NFxt = n`, а `N = sum H(n)`. Тогда:

```text
C_low(n)  = 100 × sum[k > n] H(k) / N
C_high(n) = 100 × sum[k >= n] H(k) / N
C(n)      = (C_low(n) + C_high(n)) / 2
```

Одинаковая целочисленная множественность получает один класс по середине своего
процентильного интервала. Пограничный бин целиком относится к этому классу,
поэтому фактические доли могут отличаться от заданных, особенно на малой выборке.
Процентильный интервал сохраняется для проверки границ; случайного разделения
одинаковых событий нет.

| `FxtCentralityClass` | Интервал `C(n)` |
| --- | --- |
| `0` | 0–10%: `[0,10)` |
| `1` | 10–30%: `[10,30)` |
| `2` | 30–50%: `[30,50)` |
| `3` | 50–80%: `[50,80)` |
| `−1` | Остаток 80–100%, сохранённый вне четырёх запрошенных классов |

Для интеграла используется точная таблица частот, включая значения больше 65535;
overflow отображаемой гистограммы не искажает центральность.
`hNFxtReference` и `FxtCentralityMap` одинаковы во всех файлах одного запуска:
их нельзя суммировать при объединении файлов, иначе выборка будет посчитана повторно.
Локальные `hNFxt`, `hNFxt_*` и `hFxtCentrality` можно суммировать.
Классы, рассчитанные в отдельных запусках с разными выборками, требуют общей
повторной калибровки перед совместным анализом.

## Гистограммы и рисунки

По горизонтали всегда **псевдобыстрота**, не быстрота:

```text
pT = hypot(px, py)
eta_before = asinh(-pz_CM / pT)
eta_after  = asinh(pz_output / pT)
```

Гистограммы имеют 240×150 бинов, диапазоны по умолчанию η ∈ [−6,6),
pT ∈ [0,3) ГэВ/c. Их можно изменить через `--eta-max` и `--pt-max`.
Это необработанные числа частиц на бин, без нормировки на событие, площадь бина или веса.
Выход за границы рисунка **не отбрасывает частицу**: используются underflow/overflow-бин,
а число таких записей хранится в `<имя_гистограммы>_outside_plot`.

При pT=0 и ненулевом продольном импульсе η бесконечна: запись попадает в соответствующий
крайний служебный бин и счётчик `_axial`. При нулевом трёхимпульсе η не определена:
запись идёт только в `_undefined_eta`, но остаётся в McDst и множественностях.
Сумма всех бинов, включая служебные, плюс `_undefined_eta` равна `LabParticles`.
Гистограммы множественности содержат целочисленные значения 0…65535; большие значения
попадают в overflow, а точное число остаётся в `LabMultiplicity`.

Сравнение двух гистограмм с общей цветовой шкалой, PNG и PDF:

```bash
root -l -b -q 'scripts/plot_lab.C("lab_files/sample.mcDst.root","eta_pt")'
```

Макрос визуализации работает и с полным результатом, и с `--hist-only`.
Отдельный рисунок полного FXT-распределения с цветными классами центральности:

```bash
root -l -b -q 'scripts/plot_fxt.C("lab_files/sample.mcDst.root","fxt_multi")'
```

Создаются `fxt_multi.png` и `fxt_multi.pdf`. Макрос использует общую калибровочную
выборку из результата; в легенде указаны фактические числа событий по классам.

Для объединения результатов одной выборки с одинаковыми настройками можно суммировать
гистограммы средствами ROOT. Счётчики/параметры и таблица `InputEntry` относятся к каждому
входному файлу; после механического объединения их нельзя считать глобальными идентификаторами.

## Объединение результатов

Для общего FXT-рисунка объединять файлы не требуется: каждый результат содержит
`hNFxtReference` и `FxtCentralityMap` всей калибровочной выборки запуска.
Можно передать `scripts/plot_fxt.C` любой один выходной файл.

Для одного файла с событиями и суммарными гистограммами используйте отдельную программу:

```bash
make -j4 mcdst_merge
./mcdst_merge fxt_multi.fixed.mcDst.root tmp/
# либо явно перечислить входы:
./mcdst_merge combined.mcDst.root lab_files/*.mcDst.root
```

Первый аргумент — новый выходной файл, остальные — файлы или каталоги с `.root`
(без обхода вложенных каталогов). Поддерживаются полный и QA-режимы.
Они не смешиваются в одном результате. Готовые входы повторно преобразовывать не нужно.
Существующий выход не заменяется; при ошибке временный результат удаляется.

`mcdst_merge` содержит словари `McEvent`, `McParticle`, `McRun`. Обычный `hadd`,
запущенный без этих словарей, может прочитать `McRun` как его базовый `TNamed`
и вывести `CheckByteCount`/`TKey and object retrieve disagree on type`.
Также обычный `hadd` суммирует `TParameter` по умолчанию и повторяет общую таблицу
центральности. Поэтому его результат требует отдельной проверки и восстановления
метаданных; для файлов `mcdst_lab` предусмотрен `mcdst_merge`.

Программа проверяет параметры преобразования, FXT-калибровку, оси гистограмм
и структуру деревьев. События, локальные гистограммы и счётчики суммируются,
а общие параметры, `hNFxtReference` и `FxtCentralityMap` сохраняются один раз.
При слиянии части файлов калибровка остаётся от исходной полной выборки.
Число одновременно открытых входов ROOT ограничено; ручная разбивка на пачки не нужна.

`MergeInputs` хранит путь к каждому входу, `LabSource`, смещение `FirstEntry`
и число событий `Events` в объединённых деревьях. Номера `InputEntry`/`EventNr`
сохраняются как в исходных файлах. В `MergedSources/<номер>/` находятся метаданные
каждого входа, включая его `SourceMetadata`. Верхнеуровневый `McRun` и
`SourceMetadata` берутся из первого входа и описывают именно его.

Дубликаты путей и `LabSource` отклоняются. Уже объединённые результаты повторно
не принимаются: передавайте исходные файлы `mcdst_lab` одним запуском.
Скрипт `merge.sh [INPUT_DIRECTORY [OUTPUT.root]]` вызывает эту же программу;
без аргументов сохраняются прежние пути скрипта.

## Проверки

```bash
make -j4 test-lab
# или после сборки теста через CMake:
ctest --test-dir build -R mcdst_lab_tests --output-on-failure
```

Тесты проверяют остановку Target, ускорение и направление Projectile, сохранение массы,
pT и пространственно-временного интервала, служебные координаты, пустые события и
события с 394 частицами, заряженные/нейтральные адроны, лептоны, фрагменты и неизвестные PDG,
знаки η, учёт служебных бинов, дополнительные ветви, split/unsplit McDst,
эквивалентность гистограмм обоих режимов, параллельную обработку каталогов и сохранность
существующего результата при ошибке. Проверяются имена `.mcDst.root`/`.qa.root`, отсутствие
повторного суффикса McDst и защита от совпадения имён результатов. Исходные файлы
проверяются на неизменность.
Неполные `Event`/`Particle`, вложенные split-ветви и дополнительные ветви проверяются
отдельно; при отказе существующий выходной файл должен остаться неизменным.
FXT-тесты проверяют заряженные адроны, лептоны, ядра и антиядра, нейтральные
и неизвестные PDG, каты в лабораторной системе, независимость от диапазонов рисунка,
общую центральность нескольких файлов, интеграл с нулевой множественностью,
границы четырёх классов, одинаковые множественности и совпадение QA/полного режима.
Тесты слияния проверяют полный/QA-выход, тип `McRun`, общую калибровку без дублирования,
числовые параметры, гистограммы, дополнительные ветви, происхождение событий,
несовместимые входы и количество файлов больше лимита одновременно открытых входов.
